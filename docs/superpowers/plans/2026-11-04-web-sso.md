# Web portal and SSO implementation plan

Spec: `docs/superpowers/specs/2026-11-04-web-sso-design.md`

## Global constraints

Preserve existing data, encrypted credentials, MFA settings and desktop functionality. Implement standard OIDC with host-only cookies, private Google owner allowlist, mandatory portal TOTP, and per-request token introspection. Do not commit any real secrets or the owner's email. No Baidu scans or transfers. User has authorized implementation, GitHub integration and deployment; separate account actions only when required by the active browser policy. Each repository's commits end with its issue number. Tasks in different repositories can proceed in parallel against the fixed protocol contract.

## Task 1: URL Navigator portal

Repository `work/url-navigator-sso1`, branch `codex/web-portal1`, issue #1. Implement the entire independent `web/` module including provider, Google login, SQLite persistence, mandatory MFA, logout, embedded concise Chinese UI, configurable navigation cards, production Dockerfile and config example. Follow the spec verbatim, using maintained protocol/crypto packages. Do not edit desktop behavior. Add meaningful security tests with fake upstream identity and isolated database; ensure no test bypass exists in production. Supply deployment integration instructions and local test commands. Commit with (#1). Root owns live deployment/DNS/real secrets.

## Task 2: PanSou native OIDC client

Repository `work/baidu-share-monitor-aws-arm91`, branch `codex/portal-sso98`, issue #98. Implement local|sso mode using maintained OIDC/JWT support, configured public issuer/client/callback, host-only opaque session persisted server-side, per-request introspection and app-side CSRF. Preserve local-mode behavior and encrypted MFA state. Keep `/app/login?next=` compatible by starting SSO in SSO mode, disable local MFA endpoints, protect all business routes. App logout clears its local session and navigates to the central confirmation page `/logout`. Add config/env examples, rollback docs, and focused tests for fake provider, malformed identities, expiry, provider outages, direct routes, CSRF and local-mode regression. No live mutations. Commit with (#98).

## Task 3: Quota native OIDC client

Implement local|sso mode with maintained OIDC RP library; exact same contract and fail-closed semantics as Task 2. Persist opaque server-side app sessions; no access token browser storage. Central logout confirmation `/logout`. Add deployment docs/config and focused auth tests. No live mutations. Commit with (#7).

## Task 4: Integration and review

Review each repository diff against spec and quality requirements, fix findings, then run whole-chain test using a fake upstream Google issuer/test keys (only injectable in tests) and both clients against the portal. Verify code/nonce/recovery replay, session lifetime, cross-client token mismatch, global revocation, outage handling and browser UI. Run desktop build and existing application test suites. Obtain independent whole-system security review.

## Task 5: Deployment and acceptance

Using AWS MCP and Cloudflare connector, stage portal service/TLS at nav.jomon.dev. Configure Google client callback and private owner allowlist. User completes actual Google/TOTP enrollment when needed. Back up PanSou/Quota state consistently, record counts and MFA-file hashes, deploy tested builds while retaining rollback. Cut over apps only after central login works. Validate allowed/denied/direct-access/logout behavior, compare preserved data/MFA and record deployment metadata. Push reviewed code, open/merge PRs under existing authorization, close issues only after required verification.
